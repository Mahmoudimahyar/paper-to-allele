# CV plan — closing the weaknesses the review named (2026-09-07)

The review of 2026-09-07 named the pipeline's weaknesses; the operator answered
the fifteen decisions (`CV_RESEARCH_2026-09-05.md` s23) and asked for a plan
that closes the rest with current computer-vision and image-processing methods.
This is that plan. It is ordered by return on effort, every phase names the
population it reaches (measured on the live store today), the gate it must pass
before its facts count, and the handle that withdraws it. Nothing here changes
the constitution: OCR produces proposals, a person verifies, no model makes the
final finding, and no patient image leaves the machine except by HA-013.

## Where the loss is, measured today

| population | size | what it is |
|---|---|---|
| review queue | **35,391 cells / 14,631 pages** | everything a person is asked to look at |
| label read, no box, cell INKED | **3,760 cells** | the row rules found the label; the ink says a value is printed; no engine boxed it |
| label read, no box, ink UNMEASURABLE | 657 | the ink measure could not see its own control |
| page with a locus no label anchors | **11,847 pages** | `no anchor on this document` for at least one locus; prefix binding reaches only the pages that print full allele names |
| comparison sheets refused | 2,649 cells | two people on one page; a value cannot say whose it is (HA-022) |
| ABO unknown | 8,914 pages | neither the form nor the chat gave a group |
| ROLE unknown | 4,736 pages | neither the form nor the chat gave a role |
| labelled misses (1,342 labels) | **114 cells** | a person read a value the pipeline did not; 88% of misses have their digits in the stored OCR (s11/s17) — read, not bound |
| unmeasured sources | 3,685 cells | nine rules no labelled cell has checked (s22) |

The two facts that shape the order: **the misses are a binding problem, not a
recognition problem** (the digits are usually there), and **the unmeasured mass
cannot be improved before it is measured** (round five, D8-a, is a human task
and comes first).

## Phase 0 — measure before building (human; this week)

1. The disagreement pack (D15, 56 pages, 138 cells) — settles whether the 5
   contradictions and some of the 114 misses are label errors.
2. Round five at `--n 600` (D8-a): rarity-first over the nine unmeasured sources
   with `MIN_DRAW` floors, so every source gets ≥20 readings. That converts
   3,685 tier-C cells into tier A or into withdrawals, and it is the evaluation
   set for phases 1–4.

## Phase 1 — read the whole page, everywhere (highest return)

**What.** Run the whole-page detector+recognizer (PP-OCRv6 det + the measured
best rec, `page_ocr_pass.py`) over the corpus, not the 204 pages it has touched,
in resumable batches of ~500 with the box idle between batches (the machine
powers off under sustained load). Then `page_ocr_bind` as today.

**Why it fits.** Our own detector was run on crops and rows; the 3,760 INKED
cells and the 11,847 unanchored pages are exactly the places where a
whole-page pass boxes text our row-cut pass never saw. PP-OCRv6 measured 65 of
67 exact on the bench (`ENGINE_BENCH_2026-09-05.md`).

**Gate.** Labelled recall on the `anchor found, cell INKED` and `no anchor`
strata rises with contradictions ≤ 5; every bound fact carries `value_boxes`
(s14). Source `page-ocr-bound`, its own stratum, withdrawable in one statement.

**Residual.** Pages where no local engine boxes anything: an explicit document
list to Google Vision whole-page (HA-013 permits exactly this, list by list,
key in `.env`, never from a pass that writes facts).

**Cost.** Agent: half a day to batch and resume; machine: ~23k pages of
det+rec on CPU, spread over days.

## Phase 2 — the page as a table, not a set of rows

**What.** Table structure recognition to recover the printed grid directly:
PP-StructureV3's SLANet-plus (CPU, ONNX) or a DocLayout-YOLO region detector
for the table extent, fused with the rulings we already have
(`ocr/lattice.py`, `rulings/v3+lsd+sweep`). Output: a cell grid per page, with
each locus cell as a polygon, feeding the same anchors and binders.

**Why it fits.** Every form here is a table. Today the cell is inferred from
the label's row and the rulings; where rulings are faint, the row band spans
two printed rows (the adversarial review found it), and on comparison sheets
the column decides the PERSON. A learned grid replaces three heuristics with
one measurement. Tier-A pages (91,608 cells whose geometry a person has
effectively confirmed) give a per-`family` template library for free.

**Gate.** Cell-polygon IoU against the rulings-derived cells on tier-A pages
≥ 0.8 before it is allowed to place anything; then labelled recall on the
unanchored stratum. Two-subject pages stay refused until HA-022 gives `fact` a
subject.

**Cost.** Two agent days; CPU inference is light.

## Phase 3 — normalise the image before anyone reads it

Three classical steps, each measured on the 67-crop bench and the 611 sideways
pages before it is switched on for the corpus:

* **Dewarp / perspective.** We have the ruling lines and a tilt per page;
  a homography from the four table corners (or DocTr/DewarpNet where the
  rulings are lost) straightens the grid so cells are axis-aligned and the
  slope-following row reader (`ocr/rows.py`) has less to correct.
* **Illumination and shadow.** Sauvola/adaptive thresholding and a
  background-estimate subtraction; the ink measure (`ocr/ink.py`) already
  removes rulings — the same mask feeds the recognizer.
* **Resolution.** For `mid_res` pages, 2× text super-resolution (a small
  Real-ESRGAN/SwinIR text model, CPU) against plain Lanczos + unsharp: adopt
  only if exact-match on the bench rises. Never on LOW pages that carry
  `THUMBNAIL_ONLY` — the constitution says record it, not invent it.

**Gate.** Bench exact-match and engine-agreement rate before/after; no change
to a RESOLVED value without two engines agreeing on the new one.

## Phase 4 — recognise with a grammar, and an ensemble that must agree

**What.** Extend `decode_pass.py`'s grammar-constrained CTC decoding to every
engine and every locus: the allele alphabet per locus from IMGT (`imgt_version`
is already recorded), first-field/second-field structure, expression suffixes,
and the printed forms this corpus uses (`A*24,02`, `A*24,*02`, the Bw tails).
Beam-search across the three engines' logits, not their argmax strings, and
keep the rule that a fact needs two families agreeing (D6-a rests on it: 0 of
the bench pairs agreed on a WRONG value).

**Optionally, a recognizer of our own.** Fine-tune PP-OCRv6-rec (or
TrOCR-small) on our crops: 91,608 tier-A cells as silver labels, 1,342 gold,
held-out by page family. CPU fine-tuning of a mobile rec model is hours, not
days. It is a fourth engine, never a replacement — the confirmers keep their
independence by reading their own crops from the original image.

**Gate.** Labelled correct up, contradictions ≤ 5, on round five's set;
`decode/v2` as its own `source` and stratum.

## Phase 5 — the blood group is a recognition problem now, not a window problem

48 of 96 labelled groups are missed; 18 of them the label found and
"could not read", and 8 of those pages never had a whole-page OCR (phase 1
covers them). The window (`abo_window_check.py`, HA-019) is placed; what fails
is reading a stamped or handwritten `O+`.

**What.** A tiny classifier on the located field crop — classes A/B/AB/O ×
+/−/none, trained on the ~11,000 resolved printed groups as silver labels and
validated on the 96 gold. Persian `مثبت/منفی` via `persian_pass` (done). The
chat (D1-b, done) fills the rest.

**Gate.** Labelled ABO/RH misses down with 0 wrong; source `abo-field-cls`,
stratum, `MIN_DRAW` 20 (HA-019's own gate).

## Phase 6 — role from the mark, not the word

16 labelled role misses. The forms tick a box beside `اهدا کننده` / `گیرنده`.
Measure the ink inside the box beside each label with `ocr/ink.py` — the same
measure that was right 74 of 76 times on HLA cells — and read the tick, not the
word. Source `role-tick`, its own stratum.

## Phase 7 — the DRB3/4/5 row as a three-class problem

19,372 `@drbx` confirmations are labels for a gene-name classifier on the row
crop (DRB3 / DRB4 / DRB5 / none). It replaces the `S`-for-`5` repair and the
widened-header patterns with one measured model, and it is what HA-011's
grammar v2 wants as input.

## Phase 8 — order the queue, choose the sample

A learned "worth a person's minute" score from features already stored per
cell — ink fraction and coverage, box-size deviation (`boxsize.py`, wrong 5×
as often when unlike the page), engine agreement, family, quality band, and
whether the label was read. It orders the 35,391 review cells so the human
sees the likely values first and the likely-blank last, and it drives round
six's sampling by uncertainty over the sources still thin. Expected effect is
in human minutes, so it is measured in human minutes: cells resolved per
labelled hour, round five versus round six.

## Discipline that applies to every phase

* Dry-run by default, a `source` tag and a `rule_id`, its own stratum in
  `review_pack.py`, a `MIN_DRAW` floor where a gate names a count, an `--undo`.
* A per-field status snapshot around every corpus write, and a label re-score
  after it; a rule is reviewed adversarially before its yield is believed
  (all four s20 builds were rejected first time).
* CPU-only, ONNX runtime, batched and resumable, the box idle between batches.
* No image leaves the machine except by HA-013; no PII in prompts, logs,
  fixtures or screenshots; the fabricated demo pack for anything visual.
* A pass fills only what nothing else has claimed. `caption_pass` filling a
  sheet-review withdrawal was a silent reversal; every new pass checks the
  `source` of the row it would write.
